**1. The "structurally incapable" claim is false, because Bash is an edit tool.** The doctrine's proudest sentence — the measurer can't edit, the reviewer can't fix — doesn't survive contact with the tool lists. coverage-runner and verifier both have Bash, and `sed -i`, `echo >`, and `git commit` are all Bash. What you actually have is instruction-backed restraint dressed as structural enforcement, which is precisely the thing principle 3 says it isn't. That gap matters most for the verifier: a verifier that _can_ quietly fix what it finds, and is merely told not to, is back in grade-your-own-work territory. Fixes exist — a PreToolUse hook that denies write-shaped Bash patterns for those two agents, or sandboxed read-only mounts — but until one is in place, the doctrine should state the weaker truth: these agents are _instructed_ not to edit, and the verifier's diff review is the check on whether they did.

**2. The independence of review is shallower than the doctrine treats it.** Fresh context is not independent judgment. The verifier is the same model family as the authors, loaded with the same skills, sharing the same training-induced blind spots — and the exit path's Claude Code Review is a third instance of the same reviewer. What the fresh context buys you is real (no sunk-cost attachment to the diff, no memory of the shortcuts taken) but it's protection against _motivated_ error, not _correlated_ error. If sonnet systematically believes a certain tautological assertion pattern is meaningful, author and verifier will agree on it. The planted-bad-test eval I suggested is the honest response — measure the verifier's catch rate rather than assuming it — but the doctrine itself should downgrade its claim from "independent review" to "unentangled review," and the highest-value diversity is cheap: occasionally route verification through a different model.

**3. Fail-open guards with no heartbeat means you can't distinguish "quiet" from "dead."** Principle 7's asymmetry argument is sound per-invocation, but it ignores the time dimension: a guard that fails open on a broken config fails open _forever_, silently. Nothing in the design ever confirms the hooks are alive — no counter, no periodic self-test, no "guard fired N times this run" line in loop-log. A one-line addition (each hook appends to an artifact even when passing) converts silent death into visible data. Fail-open is defensible only when liveness is observable; otherwise you've built a smoke detector with no low-battery chirp.

**4. The doctrine protects the measurement from tampering but not from being wrong.** Invariant 1 and the single-source-of-truth rule together create a blind spot: `coverage.sh` and `triage.sh` are the sole authority, reimplementation is forbidden, so no independent cross-check of the measurement can exist _by doctrine_. You even documented the known undercounting (uninstantiated templates, `#ifdef` branches) — the doctrine's answer is to write the blind spot down, not to bound it. A bug in the baseline-rewrite logic would be inherited by every subsequent iteration exactly like the "lie" invariant 1 warns about, just an honest one. The fix isn't reimplementation; it's occasional cheap triangulation — a fixture with hand-counted expected coverage that the tool must reproduce, which is a layer-1 eval the doctrine currently has no slot for because "tools/ is the authority" reads as "tools/ is axiomatic."

**5. The non-negotiable cap of 3 contradicts the loop's own epistemology.** The doctrine says loop-log exists so "is this working" gets answered with data rather than impression — and then fixes the iteration budget by impression, forever, in prose. A loop improving monotonically at iteration 3 stops; a loop that plateaued at 2 already wasted one. The principled version of the same safeguard is a stop rule conditioned on the data you're already logging (stop when marginal ceiling gain per iteration falls below a floor), with the hard cap kept as the outer bound. Relatedly, "escalation is success" is only true if escalations get _consumed_ — the design files a bd issue per blocked entry but models no human capacity, so the doctrine has no answer to a backlog of successful escalations nobody reads.

**6. The closed C-set has no amendment process.** Closing the set is correct — that's the whole defense of the denominator — but a constitution without an amendment clause fails differently: legitimate new categories pile up in `?`, each resolved one verdict at a time, and the pressure to misfile into an existing C reason grows. You're already collecting exactly the evidence an amendment process needs (`rule_would_say` vs human verdicts); the doctrine just never says "when N human verdicts share a rationale no rule captures, that's a proposal for a new closed-set member, reviewed as a diff to the rules." Same gap, incidentally, for the doctrine itself — it's stated across many files with no designated place where a principle gets revised when it loses an argument with reality.

**7. Judgment has already leaked out of skills into an agent, and the doctrine doesn't notice.** Churn-weighting, blocker-grouping, and disjoint file assignment are genuine judgment — arguably the highest-stakes judgment in the pipeline, since they set priorities — and they live in the triager _agent's_ prose, not the triage _skill_. By principle 2 they're in the wrong layer: skills are supposed to be the judgment, agents the isolation. It's benign today, but it means that judgment is invisible to anyone using the skill standalone ("what should we test next" without the loop gets a different, poorer answer than the loop would), and it's untouched by any skill-level eval.

None of this says the doctrine is wrong-headed — points 1 and 3 are implementation shortfalls against its own standards, 2 and 4 are places where it claims more than it delivers, and 5–7 are missing self-application: a system built on "never grade your own work" and "answer with data" hasn't turned either principle on its own rules. That last observation is probably the single most useful amendment: the doctrine should apply to the doctrine.
